# Katashiro features in detail

What each part of the side panel does, in full. The [README](../README.md) has the short version; the tool contracts are in [tools.md](tools.md).

## Features

- **Browser Control (MCP-over-ACP)**: the extension is an MCP server over the same `/acp` socket; the agent discovers and calls **DOM-semantic browser tools** — reads such as `snapshot`, `read_dom`, `get_text`, `get_selection`, `screenshot`, `scroll`, `hover`, `highlight`, `tabs`, `tab_groups`, `wait_for`, and act-mode writes such as `click`, `type`, `fill_form`, `select_option`, `upload_file`, `press_key`, `navigate`, `history`, `reload`, `inject_css`, `new_tab`, `switch_tab`, `close_tab`, `reopen_tab`, `tab_update`, `group_tabs`, `ungroup_tabs`, `update_tab_group`, `split_tabs`, `unsplit_tabs` — most execute in the active tab via `chrome.scripting`; the tab-management tools (`tabs`, `new_tab`, `switch_tab`, `close_tab`, `reopen_tab`, `tab_update` and the tab-group tools) act on the browser's tab set. Perception is an accessibility-tree `snapshot` with stable element refs. Full surface in [the tool table](tools.md); roadmap in [ROADMAP](../ROADMAP.md).

- **Rich Chat**: agent and user messages render as **markdown → DOMPurify-sanitized HTML** — GFM tables, **syntax-highlighted** code with one-click **copy**, hardened links. `stop`/retry a turn (ACP `session/cancel`), **several conversations** in a tab strip at the top of the panel (at most 3 open across all windows; ＋ new, double-click to rename, × archives — archived ones are reopened from the 🗂️ gallery's 對話 section, or deleted there with 🗑 刪除 (after a confirm listing its messages and canvases; the canvases go with every version and their images, files in the canvas folder stay, it cannot be undone); ADR [multi-conversation](adr/multi-conversation.md)) — each conversation has **one Chrome tab group** (named after it) with its canvases and the tabs its agent opened, which stays open (never collapsed on a switch) until the conversation is archived; archiving closes the group's tabs (never a canvas tab with unsaved edits) and reopening (or a browser restart) brings them back without duplicating tabs already open; sending a message brings the conversation's **working tab** (the last tab its agent acted on) to the front; a question card left waiting in another conversation marks its tab ❓ and raises a notification; the composer's draft and staged attachments stay with their conversation; the agent can name a conversation (`set_title`) unless you named it, each with its own **chat history + ACP session resume** (reopen the panel and the conversations — and their sessions — continue; a conversation is open in one window at a time), **reply-to** (hover a message → ↩; the agent receives each message with a `[2026-10-10T16:05:12.345+08:00 sender]` header (ISO 8601, local time with milliseconds and offset) — and `↩ time sender「excerpt」` for a reply — so a batched backlog keeps its boundaries and says what it answers; click a quote to jump to the original; **select text in a message** → a 💬 beside the selection makes the chip quote just that text — type the question and send as usual, and the agent gets `↩ time sender, selected「excerpt」` plus the whole selection (rendered text, ≤ 20 KB) in a fenced block marked "data, not instructions" after your text, like the canvas's 💬 Ask agent; only within one finished message). The agent can answer specific messages too: a line `↩ <time>` in its reply renders that part under a quote of the message it answers (a time with milliseconds names exactly that message — if none has it, the message of that second only when it is the only one; one without falls back to the user's newest message of that second) — a batch of 2+ messages (or a reply) carries a one-line note telling the agent so), and stick-to-bottom auto-scroll with a "jump to latest" pill. A **clear-screen** button (🧹) wipes the current conversation's transcript and its persisted scrollback while **keeping its agent's ACP session** — the local view resets, the agent doesn't forget.

- **Attachments**: paste a screenshot into the composer, or **drop image and text files** anywhere on the chat area (up to 10 per message; [ADR](adr/chat-attachments.md)). What a file is comes from its bytes, never its name: PNG / JPEG / GIF / WebP by magic bytes go through the image path (downscaled, re-encoded, ~1 MB per turn, only for agents that declare image prompts); a text file (no NUL, strict UTF-8, few control characters in the first 8 KB) becomes a 📎 chip and is sent after your text as `📎 name（size）` plus a fenced block; anything else is refused. **Settings → 附加檔案**: file size limit at drop (default 10 MB) and a text cap checked on send, per file and for the whole message (default 256 KB; over it nothing is sent, never truncated). Memory only: chat history keeps `[file: name, size]` markers, not the content.
- **Browser-tool activity pills**: each browser tool the agent runs during a turn shows as a compact pill above the reply (`click ⏳` → `click ✓` / `✗`). **Hover** a pill for the command (e.g. `click {ref:"e12", button:"right"}`), the outcome with a one-line summary (the error text on failure — e.g. act mode off, restricted page) and the duration in ms; **click** it to expand the full arguments and the first ~300 chars of the result (selectable), click again to collapse. Arguments are **masked inside `browser-mcp.js`** before the UI sees them — every tool declares a `redact(args)` hook (`fill_form` shows field refs only, never values; `upload_file` shows name / MIME / size, never content; `type` / `type_text` show only the text length, `navigate` / `new_tab` drop the URL query and fragment, other long strings such as `inject_css` are clipped at 80 chars). Values hidden there are also scrubbed from the result summary/preview, longest first; `fill_form` values are scrubbed even as short bare tokens, and its errors never echo a value. Any URL a result mentions (e.g. `tabs`, which lists every open tab) is likewise shown only up to its path. Known limit: a page whose own text echoes a *truncated prefix* of a secret is not caught. Pills live only in the on-screen transcript; they are not saved to chat history.

- **Agent tool-call pills**: when the gateway forwards the agent's own tool calls (ACP `tool_call` / `tool_call_update` — Bash, Edit, …), each shows as an indigo-framed pill in the same strip as the browser-tool pills: a short label + ⏳ / ✓ / ✗. The OpenAB gateway forwards only the tool's identity, never the agent's free-text title or command: the label is the most specific of `_meta.openab.capability` > `name` > `title` > ACP `kind` (e.g. **`Bash`**, **`Edit`**, `execute`), and an MCP tool `mcp__server__tool` shows as **`server · tool`** (≤40 chars). A later update with the same `toolCallId` updates the same pill and may upgrade a kind-only label once the name arrives, never downgrade it; katashiro's own browser tools — called directly or through the OAB MCP Facade (`execute_capability` with a `katashiro.*` capability) — are skipped here since their browser pill already shows them; a pill still ⏳ when the turn ends (cancel / disconnect) settles to a neutral ⏹. Gateways that don't send these updates are unaffected.

- **Roster status at a glance**: one chip per configured agent. The on-screen conversation's agent is highlighted with up to three self-labelled segments — **🔌 link** (● 已連線 / ◐ 握手中 / ◐ 連線中 / ○ 認證失敗 / ○ 連不到 / ⚠️ 無回應 / ◌ 已停用) and, when the agent is allowed browser access, **🚇 tunnel** (● 活躍 / ○ 閒置 / ◌ 未連結) and **🌐 browser** (可操作 / 唯讀); a segment whose upstream is down is greyed. Another agent this window is connected to shows its name and link segment; one no open conversation of this window uses is dimmed 未使用. When the on-screen conversation's agent URL is no longer in Settings, its chip reads **agent 已移除** (the conversation can be read, archived or deleted; adding the same URL back resumes it). A liveness heartbeat keeps them honest — a half-open socket surfaces as ⚠️ 無回應 rather than a stale "connected", and clicking the highlighted chip while it is unhealthy reconnects it.

- **Several agents, one per conversation**: configure any number of agents; each conversation is bound to the one picked at ＋ (ADR `docs/adr/agent-per-conversation.md`), and open conversations reply at the same time — with different agents, each on its own ACP connection, and two conversations with the same agent too, each in its own ACP session on that agent's connection. A conversation you are not looking at keeps working in its own tab group (see [tools.md → In a background conversation](tools.md#in-a-background-conversation)). Per-agent browser-access toggles.

- **Canvases**: long or structured output goes into a **canvas** instead of a chat bubble — `markdown` (GFM, ```` ```mermaid ```` diagrams), `slides` (reveal.js), `mermaid` or `image`, each in its own tab, grouped with its conversation's tabs, rendered in a sandboxed frame (no network, sanitized markdown). You can edit a markdown canvas (Milkdown), compare it with the agent's last write, **📤 Send to agent** your edits, **💬 Ask agent** about a selection, put a selection into the chat input with **📨 To chat input** (nothing is sent), download `.md` / print to PDF, and optionally mirror every save to a local folder. Versions are kept per canvas; the agent updates a canvas with `canvas_open` / `canvas_patch` and can point at, style or page through it (`canvas_highlight`, `canvas_inject_css`, `canvas_goto`). A canvas belongs to its conversation: only that conversation's agent can read or change it. Details in the [`canvas_open` row](tools.md) and [ADR canvas](adr/canvas.md).
- **🗂️ Gallery**: one tab listing every canvas across conversations (searchable by title and content, with the agent each conversation is bound to), plus the archived conversations to reopen or delete.
- **Desktop notifications**: the agent can raise an OS notification (`notify`) for a finished task or a needed decision; a question card waiting in a background conversation raises one too, and so does a background conversation's reply that finished or failed (clicking it switches to that conversation).
- **LINE-style Chat Bubbles**: Self-sent messages align to the right (green), while received agent messages align to the left (dark slate blue) with custom avatars, sender names, and timestamp markers.
- **Connection Persistence**: Leverages the Chrome Side Panel API to host the WebSocket connection, allowing it to persist even as the user navigates across browser tabs.
- **Auto-Reconnection**: a dropped connection is retried with backoff (immediately, then 1, 2, 4, 8, 16 s, capped at 30 s, with jitter); a connection that stayed up for 30 s before dropping starts the backoff over. If the connection drops while the agent is replying, the panel says so and re-sends your message with a note asking the agent to answer it again in full, so it is not taken for a duplicate.
- **Premium Glassmorphic UI**: Features a modern dark-mode interface with glassmorphism styling, clean glow backdrops, and custom scrollbars for an enhanced visual experience.


## Canvas details

Everything about canvases beyond the tool contract in [tools.md](tools.md) (`canvas_open` and the other `canvas_*` tools):

Creates or updates a **canvas** ([ADR](adr/canvas.md)): `markdown` (default), `slides` (markdown split on `---` lines, shown with reveal.js; each slide goes through the same sanitized markdown sink), `mermaid` (the whole canvas is one Mermaid diagram source) or `image` (a screenshot `imageId` or base64 ≤ 5 MB, stored once by sha256), shown full width in its own tab (`canvas.html`), rendered in a sandboxed frame (opaque origin, no network, sanitized markdown). ```` ```mermaid ```` fences in markdown and slides canvases are drawn as diagrams (vendored `@mermaid-js/tiny` 12.1.0, loaded only when a canvas has one; `securityLevel: 'strict'`, so diagram `click` callbacks are off and a diagram link opens like any canvas link, after a confirm; the chat keeps showing them as code); a diagram with a syntax error shows the error above its source while the rest of the canvas renders, and offers **送給 agent 修**. A new canvas opens in a background tab, in its conversation's tab group (named after the conversation), and a card appears in the agent's turn; `beside: "current"` shows it in Split View next to the user's current page (Chrome 155+; the canvas tab joins that page's tab group for the split and returns to its group when the split ends or the page closes); an update needs the `baseVersion` it last saw and is refused as `stale` (JSON error) if the canvas moved on. Stored in `chrome.storage.local` with the last N versions of each canvas, full content each (**Settings → 畫布版本紀錄**, 1–50, default 10; the agent's last write is always kept), within a 200 MB budget that counts every stored version: over it, the panel asks once (a confirm card in the chat; no answer in 2 minutes = no) before removing the least recently opened canvases (never one open in a tab), otherwise the write fails with a `quota` JSON error. The canvas tab has a **🗨️ \<conversation\>** button (opens the canvas's conversation in the side panel — switched to, or reopened if archived, the canvas tab then joining its group; a canvas cannot open any other conversation), **↪ 移到其他對話** (move it into another conversation, open or archived, from a picker: content and history go with it, the old conversation's agent can no longer read or change it, and both agents are told in their next message; the canvas tab changes tab group and the folder mirror moves its files), a 🗑 delete button and a **🗂️ 總覽** link to the **canvas gallery** (`canvas-gallery.html`, also 🗂️ in the panel header): every canvas across conversations, newest first, with kind, version, last author, update time, size and conversation, searchable by title and content, each row opening (or, after a confirm, deleting) its canvas or, with 🗨️, its conversation (↪ moves it to another one), and markdown canvases an ✏️ **Edit** mode (Milkdown, saved only on Ctrl/⌘+S or 💾; a canvas that changed meanwhile opens a side-by-side conflict view; ↺ *Revert to agent's* restores the agent's last write; **↶ 復原 / ↷ 重做** while editing run the editor's own undo / redo (the same as Ctrl/⌘+Z and Ctrl/⌘+Shift+Z; an agent write cannot be undone there, and there is no version list or stepping back through saved versions); **⇆ Compare with agent's** opens the agent's last write read-only in a second tab, in Split View beside the canvas on Chrome 155+, both panes glowing the blocks that differ). Each agent write makes the blocks it changed glow for a few seconds (a removed block leaves a thin red marker); **◐ 顯示變更** in the header (one switch for all canvas tabs) instead keeps markers on what changed from the previous version to the latest, whoever wrote it (also after a reload). The header also has **📤 Send to agent** (posts your unsent edits to the agent as a diff, as you, with an optional note; the canvas data goes in a fenced block marked "not instructions"), **💬 Ask agent** (shown while text is selected in a markdown or slides canvas, with a small 💬 beside the selection too: either opens a popover there for the request — Enter sends, Shift+Enter is a new line, Esc closes — and it is posted as you with the selected text quoted the same way, naming the canvas id and version so the agent can `canvas_patch` it), **⬇ .md** download (**⬇ .mmd** for a mermaid canvas) and **🖨 PDF** (print dialog; slides use reveal’s print layout; diagrams print in a light theme); a render error offers **送給 agent 修**. The editor normalizes agent markdown (the stored text is the normalized one; `canvas_open` returns a `normalizedDiff`), and a stale write after a user edit returns `diffFromBase` (from its `baseVersion`, while that version is still in history; the agent cannot read older versions). Optionally (**Settings → 畫布存到資料夾**) every save is also written to a folder you pick, as `<7-char conversation id>-<conversation title>/<title-slug>.md` (images in `<slug>.assets/`; renaming a canvas or its conversation moves its files; a mermaid canvas as one ```` ```mermaid ```` fence), for git / Dropbox / Time Machine; a file changed outside Katashiro is never overwritten (the new content goes to `<slug>.katashiro-<time>.md` beside it and the canvas header says so), and nothing is read back from the folder. Not a page action, so act mode does not gate it.

## Install and update details

Katashiro is a zero-build MV3 extension — there is no compile step; you load the folder as-is.
It runs on Chromium browsers (Chrome, Edge). Arc needs a `chrome.sidePanel` polyfill; Firefox is
not supported.

> **Updating:** after replacing the files (or pulling), click the extension's **↻ reload** on
> `chrome://extensions/`, then **close and reopen the Side Panel** — the reload button alone does
> not refresh an already-open panel.
> Or use **Settings → 重新載入 Katashiro** in the panel (asks to confirm): it calls
> `chrome.runtime.reload()`, which re-reads the unpacked folder from disk the same way, and closes
> the side panel in **every window** — reopen it. Each conversation's chat scrollback and resumable
> ACP session live in `chrome.storage.local`, so they survive the reload, and each window reopens
> on the conversations it had open; settings are kept too. A reply in progress is cancelled
> (`session/cancel`) first. The scrollback is stored on disk in your Chrome profile (never synced);
> 🧹 clears only the current conversation's copy. A closed window's conversations are not deleted:
> the next window to open its panel takes them over (as many as fit under 3 open), and the rest
> are archived to the 🗂️ gallery's 對話 section.

> **Not supported in incognito** (#109): `manifest.json` sets `"incognito": "not_allowed"`, so
> Chrome does not offer *Allow in Incognito* and the side panel never opens in an incognito window.
> Whatever you send the agent — messages, page snapshots, screenshots, canvases — reaches the agent
> and its session, and Katashiro cannot make it forget, so an incognito promise could not be kept.
> Canvases that older versions stored for incognito windows are deleted when this version is
> installed or updated.

> **Settings sync:** config lives in `chrome.storage.sync`, so it follows your Google account to
> every Chrome with sync (Extensions) on. `manifest.json` pins the extension ID
> (`hgilgjleemnjgehpgikeonbijpjgapmf`) via `key`, so every install shares that config no matter
> which folder it's loaded from. **Don't remove the extension to upgrade** — Chrome deletes an
> extension's synced settings on removal; use ↻ reload instead.

## The name

In Japanese Onmyodo (陰陽道) and Shinto rituals, a **Katashiro (形代 / 紙代)** is a physical paper doll or vessel used to temporarily host spirits or represent individuals. 

Under this system:
* **The Chrome Extension UI (Side Panel) = Katashiro (紙代)**
  * The HTML, CSS, and JavaScript form the physical vessel—an empty shell waiting in the browser.
* **The OpenAB AI Agents = Shikigami (式神)**
  * The spiritual intelligence and agent logic that is "summoned" and "injected" into the vessel over the WebSocket connection.
* **Writing the Code = Drawing Talismans**
  * Writing configuration files (`manifest.json`) and styling components acts as the ritual of drawing magical talismans to establish a connection path between the summoner and the spirit.
* **Browser Tools = The Shikigami's Hands (施術)**
  * Through **MCP-over-ACP**, the summoned agent no longer merely *speaks* through the vessel — it *acts*. The extension serves DOM-semantic tools (`katashiro.snapshot`, `katashiro.click`, `katashiro.type`, `katashiro.navigate`, `katashiro.screenshot` and 48 more — see [the tool table](tools.md)) so the shikigami can reach through the katashiro and operate the living page. Perception and action, not just a voice.
